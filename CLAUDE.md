# CLAUDE.md — alphaess-energy-analyzer

Open-source tool: AlphaESS Open API -> SQLite -> analysis -> offline HTML report, plus
deploy scripts for a Linux host (systemd user timer). Python 3.10+, stdlib-only at runtime.

## Golden rule: nothing author-specific
No serial numbers, hostnames, IPs, user names, home paths, locations, tariffs or credentials in
any tracked file, fixture, log, report or commit message. Everything comes from `.env`,
`config.toml`, `deploy.env` or CLI flags. Fixtures are synthetic only (`DEMO000000000001`),
generated by `python -m energy_analyzer.synthetic` — never hand-edit or commit real data.

## Layout
- `src/energy_analyzer/` — package (`synthetic.py` = fixture/selftest data generator,
  `events.py` = user events and their effects, `web.py` + `web/` = dashboard, `demo.py` =
  synthetic demo database for `serve --demo`)
- `tests/` — pytest, no network; `sample_data/` — generated API-shaped JSON
- `scripts/` — harness scripts (below); `.githooks/` — git hooks; `.claude/settings.json` — Claude hooks
- `plan.md`, `checks.md`, `progress.md` — harness working files in the repo root, **git-ignored**
  (they hold deploy evidence). Write the target as `$DEPLOY_HOST`, never the real value.

## Commands (from the repo root, Git Bash on Windows / bash on Linux)
- Setup: `python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"` (Linux: `.venv/bin/python`)
- Gate before every commit: `bash scripts/check.sh` (= `make check`)
- Full-history secret scan: `bash scripts/secret_scan.sh --history && bash scripts/gitleaks.sh history`
- Regenerate fixtures: `python -m energy_analyzer.synthetic --out sample_data --days 3`

## Hooks and scripts (deterministic rules — do not rely on memory for these)
| Where | What it enforces |
|---|---|
| `scripts/check.sh` | ruff check, ruff format --check, mypy (strict), pytest, secret scan of the working tree, selftest |
| `scripts/secret_scan.sh` | exact values read at runtime from `.env`/`deploy.env`/local user + generic rules (private IPv4, AlphaESS serial shape, /home/<user>, Windows user paths, private keys). Prints file:line only, never values |
| `scripts/gitleaks.sh` | gitleaks v8.30.1 (native binary or pinned Docker image) with `.gitleaks.toml` |
| `.githooks/pre-commit` | blocks `.env`, `deploy.env`, `config.toml`, `*.db`, keys, any git-ignored file (catches `git add -f`); runs secret_scan --staged + gitleaks staged |
| `.githooks/pre-push` | blocks force/non-fast-forward pushes, deletions, pushes to branches other than feat/ fix/ docs/ chore/ ci/ (main only at bootstrap), moving tags; scans every pushed range |
| `.claude/settings.json` -> `scripts/claude_hook.py` | PostToolUse: ruff + mypy after every `.py` edit. PreToolUse: blocks `git push --force`, push to main, `git add -A/./-f`, `--no-verify`, rebase/filter-branch |

Hooks are activated per clone with `git config core.hooksPath .githooks` (done in the dev clone).
Claude Code hooks only load when the session is started from this directory.

## Git workflow
- Conventional commits; work on `feat/v0.1.0`; push after each verified plan step.
- PR to `main`, merge only with green CI **and** explicit user approval. Tag `v0.1.0` and making the
  repo public also need explicit approval. No force-push, no history rewrite, no `--no-verify`.
- If a secret ever lands in a commit: stop, report, tell the user to rotate it first.

## Windows dev notes
- `.gitattributes` forces LF; keep `core.autocrlf=false`. Shell scripts must stay executable
  (`git update-index --chmod=+x <file>` when adding new ones).
- Docker bind mounts from Git Bash need `MSYS_NO_PATHCONV=1` and `pwd -W` (see gitleaks.sh).

## Resuming a session
Read CLAUDE.md, plan.md, progress.md; run `git status` and `git log -3`; continue at the
"Next step" recorded in progress.md.

## Web dashboard rules
- API contract: docs/web-api.md (keep it in sync with web.py). UI: vanilla JS/CSS in
  `src/energy_analyzer/web/`, no external resources, no inline styles/scripts (strict CSP).
- Never serve `shared/` or any file outside the STATIC whitelist; `.env` and the DB live there.
- Off loopback the server must have WEB_PASSWORD; deploy.sh generates it on the target and
  must never print it or move it through the local machine.
- Opening a port or changing firewall rules on the target needs the user's approval.

## Lessons (append a rule whenever a mistake is caught)
- `secret_scan.sh --tree` must include untracked, non-ignored files (`git ls-files --others
  --exclude-standard`), otherwise nothing is scanned before the first commit.
- Short remote user names are matched only as `/home/<u>`, `Users\<u>` and `<u>@`, never bare.
- setuptools >= 77: use SPDX `license = "MIT"` + `license-files`, no License classifier.
- Iterate successive pairs with `itertools.pairwise` (ruff RUF007), not `zip(x, x[1:])`.
- mypy targets 3.10, so the `tomli` fallback branch is type-checked: keep `tomli` in the dev extras.
- Rate-limit tests must timestamp inside the transport, not around the client call
  (the client sleeps before sending).
- Never write an en dash as `"–"`: ruff format turns it into a literal and RUF001 fails.
  Use `chr(0x2013)` or a plain hyphen.
- Anomaly flags need |robust z| > z_threshold AND >= min_rel_deviation (20 %) from the rolling
  median. Found when the synthetic data produced z = 3.55 on +11 % days: fix the detector,
  never the test or the default threshold.
- Program output (CLI, selftest, journals) shows paths relative to the working directory
  (`cli._show`), never absolute: absolute temp/work paths leak the home directory.
- deploy.sh deploys `git archive HEAD` (committed files only, never .env); without local rsync
  (Git Bash) it streams the same tar over ssh. Commit before deploying.
- The target-side fresh-clone check needs GitHub access; while the repo is private, clone
  from GitHub locally and move it as a `git bundle`. Repeat with a direct clone once public.
- Use a robust (Theil-Sen) slope for trends; least squares lets one anomaly day tilt it.
- Test IP literals must be documentation/loopback addresses (192.0.2.x, 127.0.0.1); private
  ranges trip the secret scan by design.
- Remote scratch files go under the install path only (a check once used /tmp on the target).
- Range analyses must load `rolling_days` of history before the range (`analyze()` does), or
  the first days of every range lose their reference.
